# ProgramLoom Data Model

Runtime date: 2026-08-08 America/New_York. Product: ProgramLoom. Seed event: `AI Engineer Sandbox Summit`.

## Modeling Rules

- All operational records are event-scoped unless explicitly global.
- Internal IDs are stable opaque IDs generated by ProgramLoom.
- External IDs are stored only in integration mapping records.
- File bytes are stored outside D1/Airtable; records hold metadata and object references.
- Public serializers are explicit projections, not raw entity dumps.
- Status, schedule, communication, integration, reset, and authorization-significant changes produce audit entries.

## Core Entities

Event configuration:

- `Event`: name, slug, description, start/end dates, timezone, branding, demo/reset flags, publication state.
- `Track`: event ID, name, color, display order.
- `Room`: event ID, name, capacity, location, display order.
- `Category`: event ID, name, review defaults, display order.
- `EventStatusConfig`: submission/session/speaker status vocabulary and allowed transitions.
- `SeedSnapshot`: seed version, fingerprint, counts, reset audit linkage.

Forms and submissions:

- `SubmissionForm`, `FormVersion`, `FormField`, `FieldOption`, `FormLayoutElement`.
- `ConditionalRule`, `RuleCondition`, `RuleAction`.
- `RoutingRule`, `RouteResult`.
- `Submission`, `SubmissionAnswer`, `SubmissionParticipant`, `SubmissionAuditEntry`, `InternalTag`.
- `PublicAccessToken` or draft/return token.

Evaluation:

- `EvaluationPlan`, `EvaluationRound`, `RubricCriterion`.
- `Evaluator`, `EvaluatorAssignment`.
- `Review`, `ReviewScore`, `ReviewComment`.
- `ConflictOfInterest`, `Abstention`, `RoundSubmissionState`, `Decision`.

Speaker/session:

- `Speaker`, `SpeakerEventProfile`, `SpeakerProfileLink`.
- `Session`, `SessionSpeaker`, `SessionStatus`.
- `PortalAccessGrant`, `PortalSession`.

Onboarding:

- `PortalTask`, `PortalTaskAssignment`.
- `PortalForm`, `PortalFormVersion`, `PortalFormResponse`.
- `FileRequest`, `ResourcePage`, `ResourceAssignment`.
- `OnboardingSnapshot` or derived view model.

Schedule:

- `ScheduleEntry`: event ID, session ID, room ID, start/end, timezone, publication state, calendar UID, calendar sequence.
- `ScheduleChange`, `ConflictRecord`, `ConflictOverride`, `ScheduleAuditEntry`.

Communications:

- `CommunicationTemplate`, `TemplateVariable`, `RenderedMessage`.
- `ReminderRule`, `ScheduledMessage`, `MessageJob`.
- `DeliveryLog`, `CalendarArtifact`, `IdempotencyKey`.

Files:

- `FileAsset`: event ID, owner type/ID, request ID, provider, bucket, object key, version, size, hash, content type, filename, visibility, status, scan status.
- `FileAccessGrant`: short-lived access or download authorization.

Integrations/API:

- `IntegrationConnection`: provider, event ID, status, configuration metadata, secret reference, last validation.
- `ExternalMapping`: provider, local entity type/ID, external type/ID, sync state.
- `SyncRun`, `SyncPlan`, `SyncPlanItem`, `SyncRecordResult`, `IntegrationLog`.
- `ApiKey`, `ApiScope`, `RateLimitBucket`.

Operations:

- `AuditEntry`, `SystemEvent`, `OutboxJob`.

## Key Relationships

- One event has many tracks, rooms, categories, forms, submissions, speakers, sessions, tasks, schedule entries, templates, and integrations.
- One form has many versions; each submission references the form version used at submit time.
- One submission has one primary participant and may have co-speakers.
- Routing rules produce route results linked to submission audit.
- Acceptance creates or updates speaker, speaker-event profile, session, and session-speaker records.
- Evaluation assignments link evaluators to submissions within a plan and round.
- Review scores link to rubric criteria and never overwrite prior-round results.
- Portal tasks assign to speakers by explicit selection or rule-expanded target sets.
- File requests produce file assets; assets may be speaker-owned, session-owned, submission-owned, or resource-owned.
- Schedule entries reference sessions and rooms; conflicts reference the affected schedule entries.
- Communication jobs reference template versions and target records; delivery logs record attempts.
- Integration mappings bind ProgramLoom IDs to Accelevents/Airtable IDs without contaminating domain IDs.

## Seed Data Shape

The seed data should include realistic AI-event content, for example:

- Workshop proposal: `Hardening Agentic Coding Workflows`.
- Talk proposal: `Eval Suites That Survive Product Drift`.
- Track conflict example: one speaker assigned to overlapping sessions in `Main Hall` and `Workshop A`.
- Room conflict example: two sessions seeded into `Workshop B` at overlapping times.
- Unscheduled accepted session: `Local Models for Event Ops`.
- Onboarding tasks: bio, headshot, slides, AV needs, consent form, schedule confirmation.

The exact seed fixture can evolve, but the required counts and conflict conditions must remain stable.

## Public Projection Rules

Public speaker projection includes:

- Name, title, company, bio, approved headshot/fallback, links marked public, assigned published sessions.

Public speaker projection excludes:

- Email, phone, portal state, private links, internal notes, evaluator data, file object keys, and onboarding status.

Public schedule projection includes:

- Published session title, description, start/end, timezone, room, track, approved speakers, deep links.

Public schedule projection excludes:

- Unpublished sessions, conflict override notes, private speaker files, internal scheduling notes, sync errors.
