## Key Source Findings

The public brief frames the replacement as an open-source alternative for the subset of Sessionboard the AI Engineer team actually uses, with cost pressure over `$40k/year`, a deadline of 2026-08-12 22:00 PT, a deployed site, source repository, and a submitted form as the competition package. It lists nine primary desired features: CFP forms with conditional logic and routing, speaker portal, templated communications with reminders/calendar invites, evaluation/scoring across rounds with optional AI, drag-and-drop agenda/conflicts/views, real-time onboarding dashboard, Accelevents one-way sync, portal resources/wiki with embeds, and embeddable mobile speaker gallery/schedule.

The attached task packet expands that brief into enforceable P0/P1/P2 implementation requirements and acceptance scenarios. For implementation planning, use the attachment matrix requirements as the most detailed contract, but preserve brief footnotes that downgrade some items: AI review is very optional, public embed examples are partly waived/best-effort, dashboard is described as optional/nice-to-have in the brief but made P0 in the task packet.

The walkthrough confirms the intended product shape: focus on the Program side rather than CRM/marketing; support event settings, abstract/session forms, public submission links, submitter/speaker portal tasks, admin submissions, evaluation plans, agenda/public display, and embeds. The speaker emphasized that fidelity to Sessionboard is less important than solving the job to be done, and called out Sessionboard slowness as an opportunity.

Official Sessionboard docs confirm the core domain surfaces: forms can collect abstracts/sessions and participants; conditional logic can show fields based on answers; public forms can be previewed/shared; accepted submissions appear in agenda; evaluation plans support anonymized review, rubrics, reminders, display fields, and multiple rounds; portals expose tasks, file requests, forms, and wiki/resources; email sends have preview and history; embeds can publish agenda/session/speaker data; the API exposes event data for integrations and custom experiences.
